01 / DATA

Preserve the difficulty mix, then sample tasks.

The source is the cvdp_agentic_code_generation_no_commercial configuration of nvidia/cvdp-benchmark-dataset, using its eval split. This experiment uses the regular v1.1.0 agentic code-generation subset, with 92 records.

01 · POPULATION92 source records

Read easy / medium / hard from each record's categories field. Do not assume a separate difficulty field.

02 · APPORTIONMENT4 / 12 / 4

Compute a 20-task allocation from the original proportions, then assign integer quotas using Hamilton's largest-remainder method.

03 · FROZEN DRAWOne list × four arms

Sample without replacement within each stratum, then shuffle. Freeze the list before formal model calls; do not redraw or replace failed tasks.

Build the three strata in original JSONL line order. Use one random.Random(20261104) instance, calling sample in easy → medium → hard order, followed by shuffle. No topic-level quotas are imposed.

The input list is exactly reproducible. This seed fixes task selection and ordering, not model generation. Across Python versions, the full record ID list and file SHA-256 hashes are authoritative. New model trajectories and scores are not guaranteed to match bit for bit.

lines = raw.splitlines(keepends=True)   # Preserve the original JSONL bytes.
rows = [json.loads(line) for line in lines]
assert len(rows) == 92
by_id = {row["id"]: line for row, line in zip(rows, lines)}

# Difficulty lives in categories, not in a separate difficulty field.
groups = {d: [r["id"] for r in rows if d in r["categories"]]
          for d in ["easy", "medium", "hard"]}
assert {d: len(v) for d, v in groups.items()} == {"easy": 17, "medium": 55, "hard": 20}
exact = {d: 20 * len(v) / 92 for d, v in groups.items()}
quota = {d: math.floor(x) for d, x in exact.items()}
for d in sorted(groups, key=lambda d: exact[d] - quota[d], reverse=True)[:20-sum(quota.values())]:
    quota[d] += 1
assert quota == {"easy": 4, "medium": 12, "hard": 4}
rng = random.Random(20261104)
redraw = []
for d in ["easy", "medium", "hard"]:   # Keep source-file order within each stratum.
    redraw.extend(rng.sample(groups[d], quota[d]))
rng.shuffle(redraw)
print("Seed-based redraw matches:", redraw == RECORD_IDS)
# IDs + byte hashes are authoritative even if a future Python changes random.sample.
selected = b"".join(by_id[record_id] for record_id in RECORD_IDS)
assert hashlib.sha256(selected).hexdigest() == SELECTED_SHA256
Path(FILENAME).write_bytes(raw)
Path("selected-20.jsonl").write_bytes(selected)
Path("selected-20-ids.json").write_text(json.dumps(RECORD_IDS, indent=2) + chr(10))
print("Verified: 92 source rows; exact 20 records written to selected-20.jsonl")

Common agent and execution limits

All arms use the same system prompt, Bash / Read / Write / Edit tools, and tool-message ID length normalization. Temperature is omitted throughout, leaving provider defaults. Each task has one sample per arm.

One worker per arm, four arms in parallel, sharing a Docker host with 2 CPUs and about 5.79 GiB RAM. Individual Bash commands time out after 90 s; the Docker agent has a 1,500 s hard timeout. The nominal 1,200 s episode budget is checked between turns.

Agents receive only public docs / rtl / verif directories, rundir, and the prompt. Reference solutions and grading tests are not mounted.

04 / VALIDATION

Validation results and scope.

The benchmark provides task-level integration evidence for the tested routing configurations. It records the quality, cost, and operational tradeoffs observed in this deployment.

13 / 20

Observed task outcomes

Capability passes 65% of the selected tasks; Stage passes 55% (11/20). Capability wins three paired tasks and loses one. Opus passes 12/20 and GLM passes 4/20. Every arm retains all 20 tasks in its denominator.

−61.7%

Recorded-usage cost versus Stage

Capability records $1.9640 versus Stage's $5.1266 using the frozen cache-aware rates. Opus responses decrease from 74 to 22, with 64 luna responses in Capability. These amounts exclude unpriced attempts and are not complete bills.

116 / 116

Original-policy replay matches

The local fake-provider replay reproduces all 116 original-policy choices, with matching initial upstream input hashes. Across both policies there are 232 fixed-history replays and zero real LLM calls. This checks routing decisions on retained histories; it does not evaluate alternative generated continuations.

What this contributes to PR review

The four-arm run records 80 official-harness outcomes on identical task inputs with a common agent image and execution limits. Both router arms use the same Switchyard revision. The attachment retains full router settings, observed model usage, paired outcomes, aggregate cost estimates, and version hashes so reviewers can inspect the tested behavior.

The evidence supports reporting the observed cost and task outcomes for this configuration. Broader claims about routing quality require repeated runs and controls that separate policy changes from model-pool and generation differences.

Interpretation limits. There is one sample per arm on 20 tasks; the paired exact McNemar p-value for Capability versus Stage is 0.625 (unadjusted). Model pools and direct-versus-relayed transports differ; generation is not coupled, and cache and host resources are shared. Capability uses more responses (436 versus 344) and has longer arm wall-clock time. A stable pass-rate gain, a causal third-tier benefit, and a latency improvement are not established.

Operational observations retained in the results

Capability has endpoint anomalies on two tasks and one directory-quota termination; Stage has one incomplete response with unknown usage. Each direct baseline has one transport failure. GLM reaches the output cap with thinking-only final content on 15 tasks. Failures and budget-limited tasks remain in the scores; cost estimates exclude unknown charges. Two DeepSeek-only wins do not establish a third-tier benefit

Replaying Capability's successful BCD and Codec histories through Stage also selects DeepSeek throughout. These successful trajectories do not depend on a routing action exclusive to Capability.

The independent runs already differ in tool use and exploration before their routing decisions diverge. Stage's escalation reflects prior lack of progress; escalation and failure occurring together does not establish causation. Monte Carlo offers a clue about mid-tier collaboration, but actual generation quality after switching models at an identical prefix has not been compared.

More iteration is an observation, not a larger budget

Capability's three wins take 16, 13, and 40 turns, versus 8, 11, and 28 for Stage. Both have the same 40-turn ceiling. The difference lies in how the chosen models continue editing, validating, and deciding to stop.

Source code and public outputs reveal differences in interfaces, timing, and repair scope. This analysis did not inspect private test source, so those clues cannot be treated as confirmed causes of a specific hidden assertion failure. A follow-up should branch from identical execution prefixes, repeat multiple generation samples, and include a matched-model-pool control.
